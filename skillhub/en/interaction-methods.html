Ways to Interact with OPCP OpenStack

OpenStack provides several ways to manage your infrastructure. Depending on your use case — quick manual operations, scripting, or full infrastructure-as-code — you can choose the approach that fits best.

Option A — OpenStack CLI

The openstack command-line client wraps the REST APIs into simple, human-friendly commands. It is the recommended approach for day-to-day operations and is used throughout this training. 

# Install the CLI
pip3 install python-openstackclient

# Examples
openstack server list
openstack network create $STUDENT_ID-my-network
openstack endpoint list

Option B — REST API (cURL / HTTP)

Every OpenStack service exposes a standard REST API (HTTP URL). You can interact with it directly using curl or any HTTP client. This is the lowest-level approach and gives you full control over every request.

To access API you need first to discover the available service endpoints (the base URLs used in your API calls), you can list them with the OpenStack CLI: 

# List all service endpoints with their URLs
openstack endpoint list -c URL -c 'Service Name'

Define the environment variable $NOVA_ENDPOINT with the corresponding value 

# 1. Retrieve the Nova (Compute) endpoint URL
#    The public URL for the "nova" service becomes your NOVA_ENDPOINT.
NOVA_ENDPOINT=$(openstack endpoint list --service nova --interface public -c URL -f value)
echo "Nova endpoint: $NOVA_ENDPOINT"

# 2. Authenticate and obtain a token
TOKEN=$(curl -si --cacert $OS_CACERT -X POST "$OS_AUTH_URL/auth/tokens" \
  -H "Content-Type: application/json" \
  -d '{
     "auth": {
       "identity": {
         "methods": ["application_credential"],
         "application_credential": {
           "id": "'"$OS_APPLICATION_CREDENTIAL_ID"'",
           "secret": "'"$OS_APPLICATION_CREDENTIAL_SECRET"'"
         }
       }
     }
   }' 2>/dev/null | sed -n 's/^x-subject-token: *//p' | tr -d '\r')
echo "Token: $TOKEN"

# You can also use option -k to skip certificate verification instead of --cacert.

# 2. List servers using the Compute API
curl -s --cacert $OS_CACERT -H "X-Auth-Token: $TOKEN" "$NOVA_ENDPOINT/servers"

Option C — OpenStack SDK (Python)

The openstacksdk Python library provides a high-level, Pythonic interface to all OpenStack services. It is ideal for writing custom scripts and automation. 

# Install the SDK
pip3 install openstacksdk
import openstack

# Connect using environment variables (OS_*)
conn = openstack.connect()

# List baremetal servers
for server in conn.baremetal.nodes():
    print(f"Node: {server.name} — State: {server.provision_state}")

# List API endpoints from the service catalog
for service in conn.identity.services():
    endpoints = conn.identity.endpoints(service_id=service.id)
    for ep in endpoints:
        print(f"{service.type} [{ep.interface}]: {ep.url}")

Option D — Terraform or OpenTofu

Terraform/OpenTofu lets you describe your entire infrastructure as code in declarative .tf files. It handles dependency ordering, state tracking, and plan/apply workflows. Hereafter examples not to be executed (just for your information) 

# Initialize and apply a Terraform configuration
terraform init
terraform plan
terraform apply
# Or, with OpenTofu:
tofu init
tofu plan
tofu apply

Example main.tf:

# Configure the OpenStack provider
terraform {
  required_providers {
    openstack = {
      source = "terraform-provider-openstack/openstack"
    }
  }
}

resource "openstack_networking_network_v2" "my_network" {
  name           = "$STUDENT_ID-my-network"
  admin_state_up = true
}

resource "openstack_networking_subnet_v2" "my_subnet" {
  name       = "$STUDENT_ID-my-subnet"
  network_id = openstack_networking_network_v2.my_network.id
  cidr       = "192.168.0.0/24"
  ip_version = 4
}

resource "openstack_compute_instance_v2" "my_instance" {
  name        = "$STUDENT_ID-my-instance"
  flavor_name = "scale-1"
  image_name  = "Ubuntu 24.04 BMPOD"

  network {
    uuid = openstack_networking_network_v2.my_network.id
  }
}

Option E — Ansible

Ansible uses YAML playbooks to automate OpenStack operations. It is well suited for configuration management and orchestrating multi-step deployments. 

# Install the Ansible OpenStack collection
ansible-galaxy collection install openstack.cloud

Example playbook (you can run it with ansible-playbook):

- name: Provision OpenStack resources
  hosts: localhost
  tasks:
    - name: Create a network
      openstack.cloud.network:
        name: $STUDENT_ID-my-network
        state: present

    - name: Create a subnet
      openstack.cloud.subnet:
        name: $STUDENT_ID-my-subnet
        network_name: $STUDENT_ID-my-network
        cidr: 192.168.100.0/24
        state: present

    - name: Create an instance
      openstack.cloud.server:
        name: $STUDENT_ID-my-instance
        flavor: scale-1
        image: image_uuid
        network: $STUDENT_ID-my-network
        state: present
        wait: true
        timeout: 1800

Which Approach to Choose?

Approach Best for Learning curve Automation-friendly
OpenStack CLI Day-to-day operations, quick tasks Low Partial (shell scripts)
REST API (cURL) Debugging, understanding the protocol High Partial (verbose)
OpenStack SDK Custom Python scripts, automation Medium Yes
Terraform Infrastructure as Code, reproducible environments Medium Yes
Ansible Configuration management, orchestration Medium Yes

In this training we primarily use the OpenStack CLI for its simplicity, but feel free to reproduce the exercises with any of the approaches above.

Summary

  • OpenStack is composed of independent services (Nova, Neutron, Cinder, Keystone, Glance).
  • You can access the infrastructure via the REST API, the OpenStack CLI, the Python SDK, Terraform, or Ansible.
  • The CLI is the simplest starting point; Terraform and Ansible are better suited for infrastructure as code.
  • All approaches authenticate using the same OS_* environment variables or application credentials.
