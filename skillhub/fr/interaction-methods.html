Méthodes d'interaction avec OPCP OpenStack

OpenStack propose plusieurs façons de gérer votre infrastructure. Selon votre cas d'usage — opérations manuelles rapides, scripting ou infrastructure-as-code complète — vous pouvez choisir l'approche la plus adaptée.

Option A — API REST (cURL / HTTP)

Chaque service OpenStack expose une API REST standard. Vous pouvez interagir directement avec elle en utilisant curl ou tout client HTTP. C'est l'approche de plus bas niveau et elle vous donne un contrôle total sur chaque requête.

Pour découvrir les endpoints de services disponibles (les URLs de base utilisées dans vos appels API), vous pouvez les lister avec la CLI OpenStack :

Définissez la variable d'environnement $NOVA_ENDPOINT avec la valeur correspondante 

# Lister tous les endpoints de services avec leurs URLs
openstack endpoint list -c URL -c 'Service Name'
# 1. S'authentifier et obtenir un token
TOKEN=$(curl -si --cacert $OS_CACERT -X POST "$OS_AUTH_URL/auth/tokens" \
  -H "Content-Type: application/json" \
  -d '{
     "auth": {
       "identity": {
         "methods": ["application_credential"],
         "application_credential": {
           "id": "'"$OS_APPLICATION_CREDENTIAL_ID"'",
           "secret": "'"$OS_APPLICATION_CREDENTIAL_SECRET"'"
         }
       }
     }
   }' 2>/dev/null | sed -n 's/^x-subject-token: *//p' | tr -d '\r')
 echo "Token: $TOKEN

 Vous pouvez également utiliser l'option -k sans certificat.

# 2. Lister les serveurs via l'API Compute
curl -s --cacert $OS_CACERT -H "X-Auth-Token: $TOKEN" "$NOVA_ENDPOINT/servers"

Option B — CLI OpenStack

Le client en ligne de commande openstack encapsule les API REST dans des commandes simples et lisibles. C'est l'approche recommandée pour les opérations quotidiennes et celle utilisée tout au long de cette formation. 

# Installer la CLI
pip3 install python-openstackclient

# Exemples
openstack server list
openstack network create $STUDENT_ID-my-network
openstack endpoint list

Option C — SDK OpenStack (Python)

La bibliothèque Python openstacksdk fournit une interface de haut niveau pour tous les services OpenStack. Elle est idéale pour écrire des scripts personnalisés et de l'automatisation. 

# Installer le SDK
pip3 install openstacksdk
import openstack

# Se connecter via les variables d'environnement (OS_*)
conn = openstack.connect()

# Lister les serveurs baremetal
for server in conn.baremetal.nodes():
    print(f"Node: {server.name} — State: {server.provision_state}")

# Lister les endpoints depuis le catalogue de services
for service in conn.identity.services():
    endpoints = conn.identity.endpoints(service_id=service.id)
    for ep in endpoints:
        print(f"{service.type} [{ep.interface}]: {ep.url}")

Option D — Terraform or OpenTofu

Terraform/OpenTofu vous permet de décrire votre infrastructure entière sous forme de code dans des fichiers déclaratifs .tf. Il gère l'ordonnancement des dépendances, le suivi de l'état et les workflows plan/apply. 

# Initialiser et appliquer une configuration Terraform
terraform init
terraform plan
terraform apply
# Ou, avec OpenTofu :
tofu init
tofu plan
tofu apply

Exemple main.tf :

# Configurer le fournisseur OpenStack
terraform {
  required_providers {
    openstack = {
      source = "terraform-provider-openstack/openstack"
    }
  }
}

resource "openstack_networking_network_v2" "my_network" {
  name           = "$STUDENT_ID-my-network"
  admin_state_up = true
}

resource "openstack_compute_instance_v2" "my_instance" {
  name        = "$STUDENT_ID-my-instance"
  flavor_name = "scale-1"
  image_name  = "Ubuntu 24.04 BMPOD"

  network {
    uuid = openstack_networking_network_v2.my_network.id
  }
}

Option E — Ansible

Ansible utilise des playbooks YAML pour automatiser les opérations OpenStack. Il est particulièrement adapté à la gestion de configuration et à l'orchestration de déploiements multi-étapes. 

# Installer la collection Ansible pour OpenStack
ansible-galaxy collection install openstack.cloud

Exemple de playbook :

- name: Provisionner des ressources OpenStack
  hosts: localhost
  tasks:
    - name: Créer un réseau
      openstack.cloud.network:
        name: $STUDENT_ID-my-network
        state: present

    - name: Créer une instance
      openstack.cloud.server:
        name: $STUDENT_ID-my-instance
        flavor: scale-1
        image: "Ubuntu 24.04 BMPOD"
        network: $STUDENT_ID-my-network
        state: present
        wait: true

Quelle approche choisir ?

Approche Idéale pour Courbe d'apprentissage
API REST (cURL) Débogage, compréhension du protocole Élevée
CLI OpenStack Opérations quotidiennes, tâches rapides Faible
SDK OpenStack Scripts Python personnalisés, automatisation Moyenne
Terraform Infrastructure as Code, environnements reproductibles Moyenne
Ansible Gestion de configuration, orchestration Moyenne

Dans cette formation, nous utilisons principalement la CLI OpenStack pour sa simplicité, mais n'hésitez pas à reproduire les exercices avec n'importe laquelle des approches ci-dessus.

Résumé

  • OpenStack est composé de services indépendants (Nova, Neutron, Cinder, Keystone, Glance).
  • Vous pouvez accéder à l'infrastructure via l'API REST, la CLI OpenStack, le SDK Python, Terraform ou Ansible.
  • La CLI est le point de départ le plus simple ; Terraform et Ansible sont mieux adaptés à l'infrastructure as code.
  • Toutes les approches s'authentifient avec les mêmes variables d'environnement OS_* ou les identifiants d'application.
