Moteur de déploiement

Difficulté : Avancé · Durée estimée : 30 min

Le DeploymentEngine orchestre l'ensemble du cycle de vie de l'infrastructure — réseaux, groupes de sécurité, instances et volumes — dans le bon ordre de dépendances. Il suit chaque ressource, effectue un rollback en cas d'échec et gère les limites de débit API avec un backoff exponentiel.

Avertissement : Deux des quatre types de ressources orchestrés par le DeploymentEngine ne sont pas encore disponibles sur OPCP :
  • Groupes de sécurité — non supportés sur OPCP ; supprimez ou commentez les entrées SecurityGroupSpec de votre configuration.
  • Volumes — le stockage bloc n'est pas supporté sur OPCP ; supprimez ou commentez les entrées VolumeSpec de votre configuration.
Les réseaux et les instances de calcul sont entièrement supportés. Les exemples de code de cette leçon sont fournis à titre de référence uniquement et doivent être adaptés avant d'être exécutés sur la plateforme.

1. Sélection du flavor et de l'image

Avant de déployer une instance, vous devez choisir un flavor (taille de la machine) et une image (système d'exploitation). Le script suivant interroge le catalogue OpenStack, affiche les options disponibles et vous demande de faire votre choix. Les variables d'environnement INSTANCE_FLAVOR et INSTANCE_IMAGE sont ensuite définies automatiquement pour le script de déploiement. 

import sys
import os
# Add the parent directory to Python path to import openstack_sdk
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from openstack_sdk.auth_manager import AuthenticationManager

# Authenticate
auth_manager = AuthenticationManager()
credentials = auth_manager.load_credentials_from_env()
connection = auth_manager.authenticate(credentials)

# --- Flavor selection ---
print("\n=== Available Flavors ===")
flavors = list(connection.compute.flavors())
for i, flavor in enumerate(flavors, 1):
    print(f"  {i}. {flavor.name}  (RAM: {flavor.ram} MB, Disk: {flavor.disk} GB, VCPUs: {flavor.vcpus})")

while True:
    choice = input(f"\nSelect a flavor [1-{len(flavors)}]: ").strip()
    if choice.isdigit() and 1 <= int(choice) <= len(flavors):
        selected_flavor = flavors[int(choice) - 1].name
        break
    print("Invalid choice, please try again.")

# --- Image selection ---
print("\n=== Available Images ===")
images = list(connection.image.images())
for i, image in enumerate(images, 1):
    print(f"  {i}. {image.name}  (Status: {image.status})")

while True:
    choice = input(f"\nSelect an image [1-{len(images)}]: ").strip()
    if choice.isdigit() and 1 <= int(choice) <= len(images):
        selected_image = images[int(choice) - 1].name
        break
    print("Invalid choice, please try again.")

# --- Set environment variables for the deployment script ---
os.environ['INSTANCE_FLAVOR'] = selected_flavor
os.environ['INSTANCE_IMAGE'] = selected_image

print(f"\n✓ INSTANCE_FLAVOR set to: {selected_flavor}")
print(f"✓ INSTANCE_IMAGE set to: {selected_image}")
print("\nYou can now run the full orchestration script (section 2).")

2. Orchestration complète

Un seul appel à deploy_infrastructure() crée toutes les ressources dans l'ordre des dépendances : d'abord les réseaux, puis les groupes de sécurité, ensuite les instances, et enfin les volumes attachés à ces instances. Les variables d'environnement INSTANCE_FLAVOR et INSTANCE_IMAGE doivent être définies au préalable (voir section 1). Vous devez également générer une clé ssh appelée 'opcp-openstack-automation-ssh-key' (utilisez "ssh-keygen -f opcp-openstack-automation-ssh-key") 


import sys
import os
import base64
# Add the parent directory to Python path to import openstack_sdk
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__ if '__file__' in globals() else os.getcwd()))))
from openstack_sdk.deployment_engine import DeploymentEngine
from openstack_sdk.auth_manager import AuthenticationManager
from openstack_sdk.network_manager import NetworkManager
from config.models import (
    DeploymentConfig, NetworkSpec, SubnetSpec,
    SecurityGroupSpec, SecurityGroupRule,
    InstanceSpec, VolumeSpec,
)

# Environment variables are loaded automatically when
# OS_APPLICATION_CREDENTIAL_ID and OS_APPLICATION_CREDENTIAL_SECRET are set
auth_manager = AuthenticationManager()
credentials = auth_manager.load_credentials_from_env()

connection = auth_manager.authenticate(credentials)

network = NetworkManager(connection)

# Get the network ID by name instead of using the name directly
student_id = os.environ.get('STUDENT_ID', 'default-student')
network_name = student_id + "-app-network"
network_obj = network.get_network_by_name(network_name)
if not network_obj:
    # Try to find any network that contains "app-network" to be more flexible
    print(f"Network '{network_name}' not found. Looking for similar networks...")
    all_networks = network.list_networks()
    app_networks = [net for net in all_networks if "app-network" in net.name]
    if app_networks:
        network_obj = app_networks[0]  # Use the first one found
        print(f"Using network: {network_obj.name}")
    else:
        raise Exception(f"Network '{network_name}' not found and no app-network found")

# Check if SSH keypair exists, if not create it
key_name = "opcp-openstack-automation-ssh-key"
try:
    # Try to get the keypair to see if it exists
    keypair = connection.compute.get_keypair(key_name)
    print(f"Keypair '{key_name}' already exists")
except Exception:
    # KeyPair doesn't exist, so create it
    print(f"Creating keypair '{key_name}'...")
    try:
        # Read public key from file
        pub_key_path = "./opcp-openstack-automation-ssh-key.pub"
        if os.path.exists(pub_key_path):
            with open(pub_key_path, 'r') as f:
                public_key = f.read().strip()

            # Create the keypair
            keypair = connection.compute.create_keypair(
                name=key_name,
                public_key=public_key
            )
            print(f"Created keypair '{key_name}' successfully")
        else:
            print(f"Warning: Public key file '{pub_key_path}' not found. "
                  f"Instance will be created without SSH keypair.")
    except Exception as e:
        print(f"Warning: Could not create keypair '{key_name}': {e}. "
              f"Instance will be created without SSH keypair.")

# Prompt the user for the instance password (entered via keyboard)
import getpass
instance_password = getpass.getpass(prompt=f"Enter password for user '{student_id}' on the instance: ")

# Cloud-init user data script for first boot
user_data_script = f"""#!/bin/bash
# Create user with the STUDENT_ID name and set password
useradd -m -s /bin/bash {student_id}
echo '{student_id}:{instance_password}' | chpasswd
usermod -aG sudo {student_id}

apt-get update
apt-get install -y nginx
systemctl enable nginx
systemctl start nginx
"""

# Base64 encode the user data script as required by OpenStack
user_data_b64 = base64.b64encode(user_data_script.encode('utf-8')).decode('utf-8')

config = DeploymentConfig(
    auth_url=credentials.auth_url,
    username=credentials.username,
    password=credentials.password,
    tenant_name=credentials.tenant_name,
    region=credentials.region,
    project_name=credentials.tenant_name,

    networks=[
        NetworkSpec(
            name=student_id + "-app-network",
            subnets=[
                SubnetSpec(
                    name=student_id + "-app-subnet",
                    cidr="192.168.1.0/24",
                    dns_nameservers=["8.8.8.8", "8.8.4.4"],
                )
            ],
        )
    ],
    security_groups=[
        SecurityGroupSpec(
            name=student_id + "-web-sg",
            description="Web traffic",
            rules=[
                SecurityGroupRule(
                    direction="ingress",
                    protocol="tcp",
                    port_range_min=80,
                    port_range_max=80,
                    remote_ip_prefix="0.0.0.0/0",
                    ethertype="IPv4",
                )
            ],
        )
    ],
    instances=[
        InstanceSpec(
            name=student_id + "-web-server",
            flavor=str(os.environ.get('INSTANCE_FLAVOR', 'scale-1')),
            image=str(os.environ.get('INSTANCE_IMAGE', 'Debian 12 LVM OPCP')),
            key_name=key_name,
            network_ids=[network_obj.id],
            security_groups=[student_id + "-web-sg"],
            user_data=user_data_b64,
            metadata={"role": "web", "env": "production", "owner": "platform-team"},
        )
    ],
    volumes=[
        VolumeSpec(
            name=student_id + "-data-volume",
            size=100,
            volume_type="classic",
            attach_to=student_id + "-web-server",
        )
    ],
)

engine = DeploymentEngine(credentials)
result = engine.deploy_infrastructure(config)

if result.success:
    print(f"Deployment {result.deployment_id} succeeded")
    print(f"Duration: {result.duration_seconds:.1f}s")
    for rtype, ids in result.created_resources.items():
        print(f"  {rtype}: {len(ids)} resource(s)")
else:
    print(f"Deployment {result.deployment_id} failed")
    for f in result.failed_resources:
        print(f"  {f.resource_type}: {f.error_message}")

3. Création de paire de clés

Avant de déployer des instances, vous devez enregistrer une paire de clés SSH dans OpenStack. Le script vérifie si la paire de clés existe déjà et la crée à partir d'un fichier de clé publique local si nécessaire. Générez une clé avec : ssh-keygen -f opcp-openstack-automation-ssh-key

import base64

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

# OS_APPLICATION_CREDENTIAL_ID and OS_APPLICATION_CREDENTIAL_SECRET are set
auth_manager = AuthenticationManager()
credentials = auth_manager.load_credentials_from_env()
vi 
connection = auth_manager.authenticate(credentials)

key_name = "opcp-openstack-automation-ssh-key"
try:
    keypair = connection.compute.get_keypair(key_name)
    print(f"La paire de clés '{key_name}' existe déjà")
except Exception:
    print(f"Création de la paire de clés '{key_name}'...")
    pub_key_path = "./opcp-openstack-automation-ssh-key.pub"
    if os.path.exists(pub_key_path):
        with open(pub_key_path, 'r') as f:
            public_key = f.read().strip()

            name=key_name,
            public_key=public_key
        )
        print(f"Paire de clés '{key_name}' créée avec succès")
    else:
        print(f"Fichier de clé publique '{pub_key_path}' non trouvé.")
        print("Générez-en une avec : ssh-keygen -f opcp-openstack-automation-ssh-key")

Les scripts cloud-init passés via user_data s'exécutent au premier démarrage. Utilisez-les pour installer des paquets, démarrer des services ou configurer l'instance.

# user_data est passé directement dans l'InstanceSpec

6. Suivi des déploiements

Chaque déploiement reçoit un deployment_id unique. L'objet résultat contient les IDs des ressources créées, les ressources en échec, la durée et les éventuelles ressources orphelines qui n'ont pas pu être nettoyées. 

# Sauvegarder l'ID de déploiement pour référence ultérieure
with open("deployment_id.txt", "w") as f:
    f.write(result.deployment_id)

# Inspecter les ressources créées
print(result.created_resources)
# {'networks': ['net-abc'], 'instances': ['srv-123'], ...}

7. Rollback automatique

Si la création d'une ressource échoue, le moteur effectue automatiquement un rollback de toutes les ressources précédemment créées dans l'ordre inverse des dépendances. Cela évite l'infrastructure orpheline. 

from openstack_sdk.deployment_engine import DeploymentError

try:
    result = engine.deploy_infrastructure(config)

    if not result.success and result.orphaned_resources:
        print("Ressources orphelines nécessitant un nettoyage manuel :")
        for orphan in result.orphaned_resources:
            print(f"  - {orphan}")
except DeploymentError as exc:
    print(f"Erreur de déploiement : {exc}")

8. Nettoyage manuel

Vous pouvez également nettoyer des ressources spécifiques par type et ID. 

resource_ids = {
    "instances": ["instance-id-1", "instance-id-2"],
    "volumes": ["volume-id-1"],
    "networks": ["network-id-1"],
}

results = engine.cleanup_resources(resource_ids)

for key, success in results.items():
    status = "ok" if success else "ÉCHOUÉ"
    print(f"  {key} : {status}")

9. Limitation de débit

Le moteur utilise un backoff exponentiel lorsque l'API OpenStack retourne des erreurs de limitation de débit (HTTP 429). Cela garantit que les déploiements aboutissent même sous forte charge API sans surcharger le plan de contrôle. 

# La limitation de débit est gérée en interne :
#   1ère tentative → attente 1 s
#   2ème tentative → attente 2 s
#   3ème tentative → attente 4 s
#   …jusqu'à un maximum configurable

# La mise en cache des ressources réduit aussi les appels API :
# - Flavors, images et réseaux sont mis en cache après la première recherche
# - Les recherches suivantes utilisent le cache au lieu de l'API

Résumé

  • L'authentification utilise des identifiants d'application chargés depuis les variables d'environnement.
  • Le moteur valide les flavors et images par rapport au catalogue OVHcloud avant la création.
  • Les paires de clés SSH sont vérifiées et créées automatiquement depuis un fichier de clé publique local.
  • Injectez des scripts cloud-init via user_data pour l'automatisation au premier démarrage.
  • Attachez des métadonnées pour le marquage et le suivi des coûts.
  • Le moteur déploie les ressources dans l'ordre des dépendances : réseaux → groupes de sécurité → instances → volumes.
  • Chaque déploiement reçoit un deployment_id unique pour le suivi.
  • En cas d'échec, le rollback automatique supprime les ressources précédemment créées.
  • Utilisez cleanup_resources() pour un démontage manuel.
  • Le backoff exponentiel gère les limites de débit API de manière élégante.
